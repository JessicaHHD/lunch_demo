# 今天吃啥 · 午饭推荐助手 Demo

一个人在办公室吃午饭的用户：设置一次口味和忌口，以后每天直接给 3 个选项，不用再翻来翻去。

## 核心流程（可实际操作）
1. **偏好**：一句话描述口味（AI 解析，当前为本地模拟）或手动勾选：口味、忌口、不要油炸、少油优先、要有主食
2. **推荐**：展示筛选过程（共 N 道 → 排除忌口 / 昨天同款 / 油炸 → 候选），给出 3 道菜，每道都标出命中的规则和推荐理由
3. **换一个**：只替换当前这张卡片，换掉的菜当天不会再出现
4. **就它了**：模拟下单，写入历史记录
5. **模拟到下一天**：验证昨天吃的主菜不再出现（包括其他店铺的同款）

## 规则设计
| 需求 | 类型 | 实现 |
|---|---|---|
| 避开不吃的食材 | 硬约束 | 规则过滤，永不放宽 |
| 连续两天不吃同一道主菜 | 硬约束 | 按“主菜标准名”过滤，跨店同款一起排除；可选“同主料也避开” |
| 少油少炸 | 强偏好 | 默认排除油炸；油量参与打分；候选不足 3 道时才放宽油炸并提示 |
| 尽量有主食 | 软偏好 | 带主食加分，无主食提示“可加一份米饭” |
| 按口味推荐 | 软偏好 | 口味命中加分；近 7 天吃过的菜和主料降权，保证每天有变化 |

硬约束只用确定性规则执行，不交给大模型判断；AI 只负责理解自然语言和生成推荐理由。

## 目录结构
```
index.html        页面入口
css/style.css     样式
js/data.js        模拟菜品数据（52 道菜，15 家店）
js/engine.js      推荐引擎：过滤 + 打分 + 多样性挑选（纯函数）
js/ai.js          AI 服务层：本地模拟 / 远程接口切换，失败自动回退
js/store.js       本地存储（localStorage）
js/app.js         页面交互
api/ai.js         Vercel 后端函数（预留的大模型接口）
tests/            推荐规则测试：node tests/engine.test.js
```

## 部署到 Vercel
1. 把整个文件夹推到一个 GitHub 仓库
2. 登录 vercel.com → Add New → Project → 导入这个仓库
3. Framework Preset 选 **Other**，构建命令和输出目录都留空 → Deploy
4. 得到 `xxx.vercel.app` 链接即可提交；之后每次 push 都会自动重新部署

## 以后接入真 AI
1. Vercel 项目 Settings → Environment Variables 添加 `AI_API_KEY`、`AI_BASE_URL`（OpenAI 兼容接口，如 `https://api.deepseek.com/v1`）、`AI_MODEL`
2. 把 `js/ai.js` 中 `provider: 'mock'` 改为 `'remote'`，push 后自动部署
3. API Key 只存在后端函数里，不会暴露在网页中；接口出错时前端自动回退到本地模拟
